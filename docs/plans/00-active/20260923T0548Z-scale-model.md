# Scale Model

**Status:** In progress
**Priority:** High (architecture cliff)
**Origin:** Principal-engineer review item #3

---

## Current model (all true today)

- Each poll fetches **all** media, enriches the full slice, scores in memory.
- Entire evaluated preview is one JSON blob: `PreviewService.PersistToDB` → `media_cache.preview_json`. Startup `LoadFromDB` reloads that blob.
- SQLite pool is **one connection**. Do not raise this; it avoids `database is locked`.
- Deletion queue is **in-memory**, hard-capped at **500**. Overflow returns `ErrDeletionQueueFull`. Orchestrator **logs and skips** (`"Deletion queue full, skipping item"`). `QueueManual` logs and `continue`s. Sunset already publishes `engine_error` and retries. Approval handoff already leaves the item pending (`TestApprovalService_ExecuteApproval_QueueFullLeavesPending`).
- `EnrichWithQueueStatus` can load up to 10k pending + 10k approved rows per preview enrich.
- Event bus drops on a full 256-buffer. SSE has `Last-Event-ID` replay on the backend; the frontend tracks `lastEventId` and does not send it on reconnect.

Silent skip is forbidden.

## Chosen scale model

**Deletion queue:** Pause dispatch when the in-memory queue is full. Do not silently skip remaining candidates. A durable DB-backed queue is a later PR — it changes crash recovery and worker ownership. This plan keeps the 500 cap and makes full **visible** (event + metric + per-group skip count). Engine evaluation stays pure.

**Preview:** Server-side pagination (summary + page) is the end state. This PR does **not** rewrite preview into pages. First slice: a hard API cap with `truncated` / `totalItems`, plus a persist size guard so we never write unbounded JSON into SQLite.

**Cache:** Chunked / normalized cache is later. Until then, refuse to persist preview JSON above the byte guard. In-memory cache may still hold the full evaluated set for analytics.

**SQLite:** Stay at `SetMaxOpenConns(1)`.

## First slice (this PR)

1. **Queue-full visibility**
   - `enqueue` increments `queueFullRejections` and publishes `deletion_queue_full` once per full burst (reset on a successful enqueue).
   - Surface the counter on worker metrics.
   - Orchestrator stops further dispatch for that disk group when `QueueFromEngine` returns `ErrDeletionQueueFull`, and records `QueueFullSkipped` on the group accumulator.
   - `QueueManual` reports `queueFullSkipped` instead of pretending those items were queued.
2. **Preview persist guard** — skip `PersistToDB` when the JSON exceeds 8 MiB. Keep the previous persisted row. Log the size.
3. **Preview API cap** — `GET /preview` returns at most 2000 items, with `truncated: true` and `totalItems` when the cache is larger. Full pagination is the follow-up.

## Later PRs (named, not started)

- Durable deletion queue (DB-backed) **or** explicit engine pause that blocks the next poll until queue depth drops.
- Paginated preview (summary + page), chunked cache.
- Frontend sends `Last-Event-ID` on SSE reconnect; global refetch on `replay_gap`.
- `EnrichWithQueueStatus` keyed lookups instead of 10k+10k loads.
